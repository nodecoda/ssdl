## 2. 词法修正

```ebnf
IDENT       = ( letter | "_" ) { letter | digit | "_" | "-" } ;
INT         = [ "-" ] digit { digit } ;
```

规则：

1. `-` **不能**出现在首字符；`->`、`...`、`..` 先于 `IDENT` 匹配。
2. 因此 `a-b` 是一个 `IDENT`，不是减法；连字符只建议用于 CPU/扩展名（`generic-rv64`、`sifive-7-series`）。
3. `INT` 全局允许负号；各产生式再声明是否接受负值：`advance.cycles` 允许负值（表示操作数可以更早读），`units`/`buffer`/`latency`/`uops`/`bitmask`/`num_ops` 必须非负。
4. `#`、`//`、`/* */`、字符串转义、`[{ ... }]` 嵌套代码块与 v1.0 相同。

## 3. 修订后的产生式

以下产生式**整体替换** v1.0 对应条目；未列出的条目不变。

### 3.1 `predicate`

```ebnf
predicate_decl
    = "predicate" IDENT [ param_list ] "=" predicate_expr ";"
    | "predicate" IDENT "{"
        predicate_field { predicate_field }
      "}" [ ";" ]
    ;

param_list
    = "(" [ IDENT { "," IDENT } [ "," ] ] ")"
    ;

predicate_field
    = "selector" "=" cxx_expr ";"
    | "assembler" "=" feature_expr ";"
    | "desc" "=" STRING ";"
    | "recompute_per_function" "=" BOOL ";"
    ;
```

- 表达式形式：纯谓词，sort 由 §4 推断。
- 块形式：指令选择/汇编匹配谓词，sort 固定为 `SEL`；`selector` 仍必写。
- 参数只在表达式形式出现；参数是操作数下标或值，不是谓词。

### 3.2 `predicate_expr`

```ebnf
predicate_expr
    = "true" | "false"
    | "not" "(" predicate_expr ")"
    | "all_of" "(" [ predicate_expr { "," predicate_expr } [ "," ] ] ")"
    | "any_of" "(" [ predicate_expr { "," predicate_expr } [ "," ] ] ")"
    | "feature" "(" IDENT ")"
    | "sched_code" "(" CODE_BLOCK ")"
    | "mc" "(" predicate_expr ")"
    | "sched" "(" predicate_expr ")"
    | IDENT [ "(" [ predicate_expr { "," predicate_expr } [ "," ] ] ")" ]
    | atom_pred
    ;

atom_pred
    = opcode_pred | operand_pred | count_pred | same_reg_pred
    | func_pred | non_portable_pred
    ;
```

- `IDENT` 后无括号是零参引用；有括号是命名谓词调用，实参个数必须等于声明形参个数。
- `opcode`/`is_reg`/… 等 atom 名是保留名，不能被 `predicate` 声明复用。
- `reg_is` 的下标与 `imm_*` 的下标允许 `INT` 或谓词参数 `IDENT`。
- 空 `all_of()` 为真，空 `any_of()` 为假；二者 sort 都是 MC（见 §4）。

操作数下标：

```ebnf
operand_index = INT | IDENT ;
reg_is        = "reg_is" "(" operand_index "," ( IDENT | reg_ref | set_expr ) [ "," mapper_arg ] ")" ;
```

### 3.3 `feature`

```ebnf
feature_decl
    = "feature" IDENT ":" { feature_field [ "," ] } ";"
    ;

feature_field
    = "kind"               "=" feature_kind
    | "mattr"              "=" STRING
    | "desc"               "=" STRING
    | "implies"            "=" ident_list
    | "field"              "=" STRING
    | "value"              "=" STRING
    | "inline_behavior"    "=" inline_behavior
    | "version"            "=" STRING
    | "experimental"       "=" BOOL
    | "bitmask"            "=" "{" "group" "=" INT "," "bit" "=" INT "}"
    | "positive_directive" "=" STRING
    | "negative_directive" "=" STRING
    ;
```

`mattr` 是 `-mattr` 名字；合法性表见 §6。

### 3.4 资源属性分隔符

```ebnf
resource_decl
    = "resource" IDENT [ ":" res_prop { ( ":" | "," ) res_prop } ] ";"
    ;

res_group_decl
    = "res_group" IDENT "=" ident_list
      [ ":" res_prop { ( ":" | "," ) res_prop } ] ";"
    ;
```

### 3.5 `sti_function` 与 `tii_predicate` 的尾随 `;`

```ebnf
sti_function = "sti_function" IDENT ":" IDENT "{" { sti_function_item } "}" [ ";" ] ;
tii_predicate = "tii_predicate" IDENT "=" statement [ ";" ] ;
```

`return` 语句自带 `;`，因此 `tii_predicate X = return P;` 合法；`switch` 语句以 `}` 结束，因此 `tii_predicate X = switch opcode { ... };` 也合法。两者都不再需要第二个 `;`。

### 3.6 `itineraries`

```ebnf
itineraries_decl
    = "itineraries"
      [ ":" itin_prop { ":" itin_prop } ]
      "{" { itineraries_item } "}"
    ;

itin_prop
    = "sched_model"          "=" IDENT
    | "packetizer_namespace" "=" STRING
    ;
```

绑定规则见 §7。

### 3.7 列表记法（统一说明，不新增语义）

v1.0 的“一套 `[...]`”在不同条目里重复了七次。1.1 用参数化记法描述，元素产生式仍各自定义：

```text
LIST(T) = "[" [ T { "," T } [ "," ] ] "]"
```

| 位置 | 元素 `T` | 允许 `...` | 允许范围 |
|---|---|---|---|
| `ident_list` | `IDENT` | 否 | 否 |
| `int_list` | `INT` | 否 | 否 |
| `bit_list` | `BOOL` | 否 | 否 |
| `set_item` | `IDENT` / `...` / `set_expr` | 是 | 否 |
| `int_item` | `INT` / `... IDENT` / `INT ".." INT` | 是 | 是 |
| `inst_item` | `IDENT` / `regex(STRING)` | 否 | 否 |
| `sched_rw_list` | `IDENT` | 否 | 否 |

“原则 6”里“所有列表都支持空列表、尾随逗号、展开、范围”改为：**所有列表支持空列表与尾随逗号；展开与范围只在元素产生式声明的地方可用**。

### 3.8 `attr_expr` 的优先级

```text
高 → 低：  !            （右结合）
          == != < > <= >=（非结合）
          &&           （左结合）
          ||           （左结合）
括号覆盖优先级。
```

这消解了 v1.0 §3.16 的左递归歧义。类型规则见 §5。

## 4. 谓词排序（MC / SCHED / SEL）

### 4.1 三个 sort

| sort | 对应 LLVM | 出现位置 |
|---|---|---|
| `MC` | `MCInstPredicate` 及其子类 | `sti_decl.default`、`tii_predicate`、`equiv_class`/`dep_breaking_class`、调度谓词中的 atom |
| `SCHED` | `SchedPredicateBase` 及其子类 | `variant`/`read_variant` 的 `case`、`sched_code`、`feature` |
| `SEL` | `Predicate<code>` + `AssemblerPredicate` | 块形式 `predicate` 的 `selector`/`assembler` |

`SEL` 不是调度谓词，不能出现在 `predicate_expr` 里。

### 4.2 推断规则

| 表达式 | sort |
|---|---|
| `true` / `false` | MC |
| `atom_pred`（`opcode`、`reg_is`、`same_reg`、`non_portable` …） | MC |
| `feature(X)` | SCHED |
| `sched_code(c)` | SCHED |
| `mc(e)` | MC（要求 `sort(e)=MC`，否则错误） |
| `sched(e)` | SCHED（`MC` 自动提升） |
| `all_of(e1..en)` / `any_of(e1..en)` | 全部 MC → MC；任一是 SCHED → SCHED；空 → MC |
| `not(e)` | `sort(e)` |
| 命名谓词 `P` 或 `P(args)` | `sort(P)`；`P` 不能是 SEL |

### 4.3 提升规则

```text
to_sched(e) = e                     if sort(e) = SCHED
            = MCSchedPredicate<e>   if sort(e) = MC
            = error                 if sort(e) = SEL
```

- `variant` / `read_variant` 的 `case`：`to_sched(case_expr)`。
- `sti_decl.default`、`tii_predicate` 的 `return`、`equiv_class` 谓词：必须是 MC；SCHED/SEL 报错。
- 表达式形式的 `predicate P = e;` 没有上下文，`sort(P)=sort(e)`，两种都可以；使用处再做检查。

### 4.4 norm

```text
MC atom                 → CheckOpcode / CheckRegOperand / CheckSameRegOperand / CheckNonPortable / ...
MC all_of(...)          → CheckAll<[...]>        （空 → TruePred）
MC any_of(...)          → CheckAny<[...]>        （空 → FalsePred）
MC not(e)               → CheckNot<...>
SCHED feature(X)        → FeatureSchedPredicate<X>
SCHED sched_code(c)     → SchedPredicate<[{ c }]>
SCHED all_of(e...)      → AllOfSchedPreds<[to_sched(e)...]>
SCHED any_of(e...)      → AnyOfSchedPreds<[to_sched(e)...]>
SCHED not(e)            → NotSchedPred<to_sched(e)>
SCHED none_of(e...)     → NoneOfSchedPreds<[to_sched(e)...]>
predicate P = e;        → MC: MCInstPredicate P；在调度上下文用时 MCSchedPredicate<P>
                          SCHED: SchedPredicateBase P
predicate P { selector = ...; } → Predicate<selector 代码> + AssemblerPredicate<assembler>
```

**修正 v1.0 §4.4**：表达式形式**不再**展开成 `Predicate<...>`；`Predicate<...>` 只属于块形式的 `selector`。这是 M3 的关闭方式。

### 4.5 保留名与错误

- Atom 名（`opcode`、`pseudo`、`is_*`、`imm_*`、`reg_is`、`same_reg`、`num_ops`、`func`、`func_tii`、`non_portable`）以及 `feature`、`sched_code`、`mc`、`sched`、`all_of`、`any_of`、`not`、`true`、`false` 都是保留名，不能声明为谓词。
- 未声明的裸 `IDENT`、参数个数不符、循环引用、`mc(SCHED)`、MC 上下文里的 SCHED/SEL、调度表达式里的 SEL 都是编译期错误（M10）。

示例：

```text
predicate IsZeroReg(i) = reg_is(i, ZeroRegs);          # MC
predicate IsZeroIdiom = all_of(opcode([ORR]), IsZeroReg(1));  # MC
predicate HasExt = feature(StdExtI);                   # SCHED
predicate Code = sched_code([{ TII->isVRegCopy(MI) }]);        # SCHED

variant W_ALU {
    case all_of(opcode([ORR]), IsZeroReg(1)): [W_ALU]; # MC → 自动提升为 SCHED
    case all_of(feature(StdExtI), opcode([ORR])): [W_ALU]; # SCHED，MC 子项被包装
    default: [W_ALU];
}
```

## 5. `set` 属性契约（M5）

v1.0 写 `inst(category == logical)`，但 LLVM 的 `Instruction` 没有 `category` 字段，也没有规定属性 universe。1.1 不再假装存在通用 schema，而是把它定义为**宿主契约**。

### 5.1 规则

1. `set` 的属性名由宿主 schema 定义；SSDL 只规定引用与求值规则，不新增关键字。
2. 宿主必须为 `inst` 与 `reg` 分别声明：属性名、类型（`bool` / `int` / `string`）、取值来源、以及该实体类的规范顺序（通常就是 TableGen 的 def 顺序 / opcode 枚举顺序）。
3. 类型规则：
   - `==` / `!=`：两侧类型必须相同；
   - `<` `>` `<=` `>=`：只允许 `int`（字符串不定义序）；
   - `&&` / `||` / `!`：只允许 `bool`；
   - 优先级按 §3.8。
4. 未知属性、缺失取值、类型不匹配都是**编译期错误**；缺失值不得默认为 `false`。

4a. 取值域是三态：`true` / `false` / **unknown**。JSON schema 用 `null` 表示 unknown（对应 TableGen 记录里未推断的 `?`，例如 `mayLoad = ?`）。unknown 参与任何比较、或作为布尔条件，都是编译期错误。

4b. 布尔连接按三值逻辑传播，避免把 unknown 静默折成 `false`：

```text
unknown && false = false        unknown && true  = unknown
unknown || true  = true         unknown || false = unknown
!unknown         = unknown
```

被 unknown 污染的实体**不进入**结果集，同时保留 4a 的错误。这样"取反未知"不会翻转成一个看似合理的答案。
5. 名字大小写敏感；`inst(...)` 只能引用 inst 属性，`reg(...)` 只能引用 reg 属性。
6. 展开顺序：宿主规范顺序；`[A, ...B, C]` 为 `A ++ B ++ C`；重复项按首次出现去重（稳定）。
7. `[a..b]`：闭区间升序；`a > b` 为空集还是错误？1.1 规定为**错误**，避免静默空集。
8. `set` 可以引用其他 `set`；允许前向引用；循环引用是错误。
9. `set` 的展开结果是 `list<Instruction>` / `list<Register>`，不保留属性表达式。

### 5.2 参考 profile（非规范性，RISC-V）

| 实体 | 属性 | 来源 |
|---|---|---|
| inst | `is_pseudo` | `MCInstrDesc::isPseudo()` |
| inst | `may_load` / `may_store` | `MCInstrDesc::mayLoad()` / `mayStore()` |
| inst | `is_branch` / `is_terminator` / `is_call` / `is_return` | 对应 `MCInstrDesc` 查询 |
| inst | `is_commutable` / `has_side_effects` | 对应 `MCInstrDesc` 查询 |
| inst | `is_codegen_only` | `MCInstrDesc::isCodeGenOnly()` |
| inst | `namespace` | TableGen `Instruction::Namespace` |
| reg | `is_virtual` | `Register::isVirtual()` |
| reg | `is_zero` | RISC-V：`reg == X0` |
| reg | `is_fixed` | 寄存器是否被保留/固定 |
| reg | `register_class` | 宿主寄存器类名（字符串） |

`category == logical` 不是 LLVM 内建属性；宿主若需要，必须自己声明 `category`（例如由指令类名或 `Namespace` 派生），否则 v1.0 的示例这一行应改为 `is_pseudo == false && may_load == false` 之类的真实属性。

**实现状态**：已实现（`tools/ssdl/sets.py`），三值语义见 4a/4b，自检 `unknown_attribute_is_not_false`；schema 导出见 `tools/ssdl/schema.py`。

## 6. `feature` 合法性表（含 E1）

| `kind` | 必须写 | 可以写 | 不可写 |
|---|---|---|---|
| `plain` | `mattr`、`field`、`value` | `desc`、`implies`、`inline_behavior` | `version`、`experimental`、`bitmask`、`*_directive` |
| `extension` | `version` | `field`、`value`（成对）、`desc`、`implies`、`experimental`、`bitmask` | `mattr`、`*_directive` |
| `tune` | `positive_directive`、`field`、`value` | `negative_directive`、`desc`、`implies`、`inline_behavior` | `mattr`、`version`、`experimental`、`bitmask` |

- `mattr` 是 `-mattr` 名字。`plain` 无法从 SSDL 标识符推导它（`Feature64Bit` → `"64bit"`），所以必写。
- `extension` 的 `Name` 由 `RISCVExtension` 从 record 名推导（去 `FeatureStdExt`/`FeatureVendor`、小写、实验性加前缀），因此禁止 `mattr`，避免两套命名。
- `tune` 的 `Name` 是 `positive_directive`。
- `extension` 的 `implies` 只能指向 extension；`tune` 只能指向 tune（`RISCVExperimentalExtension` 的 implies 是 `list<RISCVExtension>`，类型更严格）。
- `version` 必须是 `MAJOR.MINOR`（两个非负整数）。

## 7. `itineraries` 绑定（M6）

### 7.1 规则

1. 顶层 `itineraries` **必须**写 `sched_model = IDENT`；该名字必须是已声明的 `machine` 定义（不能是 `machine X = Y` 的别名）。
2. `machine` 内部的 `itineraries` **禁止**写 `sched_model`；包含它的 machine 自动成为 owner。
3. `itin X { ... }` 定义 `InstrItinClass X` 及其 `InstrItinData`；`itin_class X;` 只声明空的 `InstrItinClass X`。两者同名即重复定义错误。
4. 指令到 itinerary class 的绑定由宿主指令定义提供（`Instruction.Itinerary = IIC_x`），不在 SSDL 里写；`map_itin` 只把 itinerary class 映射到 `SchedReadWrite`。
5. `func_units` / `bypasses` 是 itinerary 块级共享列表；`itin` 内的 `bypasses` 覆盖/补充该 itin 自己的 bypass 列表。
6. `packetizer_namespace` 原样传给 `ProcessorItineraries.PacketizerNamespace`。

### 7.2 norm

```text
itineraries : sched_model = M : packetizer_namespace = "P" { ... }
  → ProcessorItineraries<[func_units], [bypasses], [InstrItinData...]> { PacketizerNamespace = "P" }
  → SchedMachineModel M.Itineraries = <该记录>

machine M { itineraries { ... } }
  → 同上，但 owner 隐式为 M
```

## 8. norm 增量

1. **`map` 混写**：一个 `map` 同时含 `IDENT` 与 `regex(...)` 时，拆成两条 `InstRW`：
   - `def IRW_<names>_instrs : InstRW<[...], (instrs ...)>;`
   - `def IRW_REGEX_<sanitized>_regex : InstRW<[...], (instregex "...")>;`
   两条记录共享同一个 `rw` 列表。纯 `IDENT` 或纯 `regex` 的命名保持 1.0 的 `IRW_...` / `IRW_REGEX_...`。
2. **`advance`**：`cycles` 必写，允许负值；省略 `writes` 表示对所有写生效。
3. **`machine`**：`X` → `XModel : SchedMachineModel` + `X : RISCVProcessorModel`（无 `features` 时用 `RISCVTuneProcessorModel`）；`machine X = Y` → `ProcessorAlias`。
4. **谓词**：按 §4.4；表达式形式不再产生 `Predicate<...>`。
5. **`unsupported_features`**：`[Name...]` → `UnsupportedFeatures = [Has<Name>...]`（`list<Predicate>`）。
6. **`itineraries`**：按 §7.2。

## 9. 调度词表所有权（M11）与机器级命名（M12）

### 9.1 词表是目标级的

`write` / `read` / `write_seq` / `func_unit` / `bypass` / `itin_class` 可以写在任意 `machine` 块里，但它们的**作用域是目标**，不是机器：

- 展开时提升到单一目标命名空间，只发射一次；
- 同名重复声明必须同 kind 且同形，否则报 `conflicting declaration of scheduling write 'W'`；
- 引用在目标命名空间内解析，因此 machine B 可以不重复 `write W_ALU;` 就直接 `bind W_ALU -> ...`；
- `bind` / `advance` / `map` / `map_itin` / `variant` / `read_variant` / `alias` 仍是机器级，发射在 `let SchedModel = ... in { ... }` 内。

依据：上游把 `WriteIALU` 定义在目标级（`RISCVSchedule.td:16`），指令通过 `Sched<[WriteIALU]>` 引用；模型只提供 `WriteRes<WriteIALU, [PipeAB]>`（`RISCVSchedSiFive7.td:335`）。`WriteSequence` 的 `SchedModel` 字段被 SubtargetEmitter 显式忽略，所以全局发射后取值 `?` 是正确形状。

### 9.2 机器级记录必须带 machine 前缀

TableGen 的 def 名全局唯一，而机器级记录（`WriteRes`/`ReadAdvance`/`InstRW`/`ItinRW`/`SchedAlias`/变体/队列）天然同名。上游用 `defm` 造出 `SiFive7PipeA`（`RISCVSchedSiFive7.td:1564`）；展开器等价地使用 machine def 名前缀：

```text
<M>_WR_<W>        <M>_RA_<R>          <M>_IRW_<...>
<M>_SchedAlias_SRC_DST                <M>_<W>Variant
<M>_SSDLVariantAlias_<W>              <M>_LoadQueue_<R>
<M>_StoreQueue_<R>                    <M>_ITINRW_<...>
```

用户命名的机器级记录（`resource`、`res_group`、`reg_file`）保持原名；跨 machine 重名是错误，诊断必须直接说明"资源名是全局 def，改名"。

### 9.3 例子

```text
machine A {
    resource P : units = 1;
    write W_ALU;
    read  R_ALU;
    bind W_ALU -> [P], latency = 1;
    advance R_ALU : cycles = 1;
}
machine B {
    resource Q : units = 2;
    write W_ALU;          # 允许：与 A 的声明同形，提升后只发一次
    read  R_ALU;
    bind W_ALU -> [Q], latency = 2;
    advance R_ALU : cycles = 2;
}
```

```tablegen
def W_ALU : SchedWrite;
def R_ALU : SchedRead;

let SchedModel = AModel in {
  def P : ProcResource<1>;
  def A_WR_W_ALU : WriteRes<W_ALU, [P]> { let Latency = 1; }
  def A_RA_R_ALU : ReadAdvance<R_ALU, 1>;
}
let SchedModel = BModel in {
  def Q : ProcResource<2>;
  def B_WR_W_ALU : WriteRes<W_ALU, [Q]> { let Latency = 2; }
  def B_RA_R_ALU : ReadAdvance<R_ALU, 2>;
}
```

### 9.4 `variant` 分支的实体化（M13）

`variant` / `read_variant` 的 subject 在 TD 里必须变成 `SchedAlias<subject, Variant>`，因此 subject 自身不能再带 `WriteRes`/`ReadAdvance`。展开器按以下规则实体化，用户语法不变：

| SSDL 写法 | 展开 |
|---|---|
| `bind W -> [R], ...` + `variant W` | `def <M>_WRes_W : SchedWriteRes<[R]> { ... }`（不再发 `WriteRes<W, [R]>`） |
| `variant W` 分支里的 `W` | `<M>_WRes_W` |
| `advance R : cycles = C : writes = [...]` + `read_variant R` | `def <M>_RAdv_R : SchedReadAdvance<C, [...]>` |
| `read_variant R` 分支里的 `R`，无 `advance` | `ReadDefault` |

约束：variant subject 不能同时是 `alias` 的源或目标；subject 之间形成环时报 `variant cycle: A -> B -> A`，不能让 TableGen 去挂死。依据与证据见 `2026-11-16-ssdl-parser-notes.md` §16。

### 9.5 不改变的性质

- 仍是 9 个顶层关键字：词表提升是语义作用域，不是新语法；
- 仍无 base：机器之间不互相继承，只是共享目标词表；
- 仍无元编程：前缀是展开规则，用户看不到也不需要写。
