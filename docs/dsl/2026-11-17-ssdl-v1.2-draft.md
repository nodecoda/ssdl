# SSDL 1.2 Draft：RISC-V 领域参数化

- date: 2026-11-17
- status: **Draft（规范性增量）**
- 基线：`2026-11-16-ssdl-v1.0-final.md` + `2026-11-16-ssdl-v1.1-draft.md`
- 依据：`2026-11-17-riscv-sched-census.md`、`2026-11-17-riscv-sched-families.md`、`2026-11-17-ssdl-family-expansion.md`
- 不改变：**9 个平级顶层关键字**；无 base/扩展；无通用元编程。

---

## 0. 一句话

1.2 只做一件事：给 RISC-V 的**模型族**与**词表维度**一个可枚举、可检查的写法。它不新增顶层关键字，也不允许任意字符串拼接或递归。

三个新增构造都挂在既有关键字上：

| 构造 | 挂在哪 | 替代的上游写法 |
|---|---|---|
| `machine F(p: INT, b: BOOL)` + `machine X : F(args)` | `machine` | `class SiFive7SchedMachineModel<int vlen>` + `def` 成员 |
| `set AXIS = [...] : kind = dimension;` | `set` | `defvar SchedMxList = [...]` + `foreach` |
| `Base[AXIS]` / `Base[AXIS in [...]]` | 标识符 | `name # "_" # mx` / `defm` |

---

## 1. 变更清单

| ID | 变更 | 类型 |
|---|---|---|
| C1 | `machine` 增加可选参数列表；`machine X : F(args)` 实例化族 | 文法/语义 |
| C2 | `set` 增加 `kind = dimension` 与 `name_format` | 文法/语义 |
| C3 | 维度化标识符 `Base[AXIS, ...]`，支持稀疏成员 `in [...]` 与 `worst(AXIS)` | 文法/语义 |
| C4 | 数值字段允许有界整数表达式（参数、维度投影、`+ - * / // %`） | 语义 |
| C5 | 覆盖性：同一站点的 `write` 与 `bind` 成员集必须一致，错误带源位置 | 语义 |
| C6 | 投影（`worst`、`legal_sew`、`cycles`）由宿主 profile 提供，语言只定调用契约 | 语义 |
| C7 | 名称生成规则：每个轴一个 `name_format`，只允许 `{value}` 替换 | 语义 |

C1–C3 是语法可见的；C4–C7 是 norm 阶段的规则，用户只在诊断里看到。

---

## 2. 文法增量

以下产生式**追加**到 v1.0 §3；未列出的条目不变。

```ebnf
machine_decl
    = "machine" IDENT [ "(" [ param { "," param } [ "," ] ] ")" ]
      ( "{" { machine_item } "}" | ":" IDENT "(" [ arg { "," arg } ] ")" "{" { machine_item } "}" )
    | "machine" IDENT "=" IDENT ";"
    ;

param
    = IDENT ":" ( "INT" | "BOOL" )
    ;

arg
    = INT | BOOL
    ;

set_decl
    = "set" IDENT "=" set_expr ";"                       (* v1.0 *)
    | "set" IDENT "=" ( "[" [ dim_value { "," dim_value } [ "," ] ] "]" | INT ".." INT )
      ":" "kind" "=" "dimension"
      [ "," "name_format" "=" STRING ]
      ";"
    ;

dim_value
    = IDENT
    ;

dim_index
    = "[" dim_use { "," dim_use } [ "," ] "]"
    ;

dim_use
    = IDENT
    | "worst" "(" IDENT ")"
    | IDENT "in" "[" [ IDENT { "," IDENT } [ "," ] ] "]"
    ;
```

`dim_index` 出现在 v1.0 中所有 `IDENT` 作为“调度写/读名字”的位置：`write`、`bind`、`advance`、`map` 的 `sched_rw_list`、`variant` 的 `case`。

## 3. 语义

### 3.1 机器族（C1）

```text
machine SiFive7(vlen: INT, has_dual_valu: BOOL) {
    resource PipeA : units = 1;
    ...
}

machine sifive-7-series : SiFive7(512, false) {
    ...
}
```

- 参数只有 `INT` / `BOOL` 两种；**没有** NAME/枚举类型。`fp_latencies` 这类枚举轴上移为布尔选择器（`low_fp_latencies: BOOL`）或由宿主 profile 决定。
- 参数只能出现在数值字段的表达式里（`latency = vlen / 128`），**不能**参与标识符拼接。
- 族声明本身不发射记录；只有实例发射。实例的记录名带实例前缀（v1.1 M12）。
- `machine X = Y;` 仍是别名（`ProcessorAlias`），与实例化不同：别名不复制记录。

### 3.2 维度声明（C2）

```text
set LMUL = [MF8, MF4, MF2, M1, M2, M4, M8] :
    kind = dimension,
    name_format = "_{value}";

set NF = 2..8 : kind = dimension, name_format = "{value}";

set EEW = [8, 16, 32, 64] : kind = dimension, name_format = "e{value}";
```

- `kind = dimension` 把元素类型从“指令/寄存器引用”改为“名字成员”。
- `name_format` 只允许一个 `{value}` 占位符；不允许表达式、多个占位符或引用其它轴。缺失时默认 `"_{value}"`（`WriteVLDE` + `MF8` → `WriteVLDE_MF8`）。
- 维度是**目标级**的，与 v1.1 §9.1 的调度词表同作用域；不能写在 `machine` 里。

**为什么需要 `name_format`**：上游把 NF/EEW 嵌在名字里（`WriteVLSEG3e16_M1`），而 `WriteType` 是被指令 `SchedRW` 引用的语义名字，不能随意重命名。Step 3 实测 SiFive7 有 270 个这样的组合名；如果 v1.2 强制 `Base_NF_EEW_LMUL`，所有引用都要改，等价性直接破裂。受控的 `{value}` 替换是唯一既能保留名字、又能让轴可枚举的方案。

### 3.3 维度化标识符（C3）

```text
write WriteVLDE[LMUL];
bind  WriteVLDE[LMUL] -> [VCQ, VL] { latency = 4; }

write WriteVLSEG[NF, EEW, LMUL];
bind  WriteVLSEG[NF, EEW, LMUL] -> [VCQ, VL] { ... }

write WriteVLDE[LMUL in [MF8, MF4, MF2]];   # 稀疏：只声明这三个
write WriteVLDE[worst(LMUL)];               # 伪成员：只生成 _WorstCase
```

展开规则（按轴顺序拼接 `name_format`）：

```text
WriteVLSEG[NF=3, EEW=16, LMUL=M1]
  → "WriteVLSEG" + "3" + "e16" + "_M1"
  → WriteVLSEG3e16_M1
```

- **稀疏成员**是显式意图，不是漏绑。`W[AXIS in S]` 的成员集就是 `S`；新增轴值时，稀疏站点**不**被要求覆盖新值。
- `worst(AXIS)` 展开为一个伪成员，后缀固定为 `_WorstCase`；它不参与成员计数，也不出现在 `in [...]` 里。
- 多维索引按笛卡尔积展开；不同轴的值不能重名（展开后冲突是错误）。

### 3.4 表达式（C4）

数值字段（`latency`、`uops`、`cycles`、`release`/`acquire` 的元素）允许：

```text
expr = INT | param | projection "(" [ expr { "," expr } ] ")"
     | expr ( "+" | "-" | "*" | "/" | "//" | "%" ) expr
     | "(" expr ")"
```

- 投影由宿主 profile 提供：`worst(LMUL)`、`legal_sew(LMUL)`、`cycles(LMUL, SEW, NF, VLEN)`。
- 无递归、无自定义函数、无字符串操作、无副作用。
- 除零、非整数结果、未知投影都是编译期错误。

### 3.5 覆盖性（C5）

对每个 `machine` 实例：

1. 每个维度化 `write` 的成员集必须与对应 `bind` 的成员集**完全一致**；
2. 每个 `bind` 的名字必须对应已声明的 `write`（或 v1.0 的目标级词表）；
3. 诊断必须带 SSDL 源位置与轴名：`machine X: bind W_C has no write (line 12, axis LMUL)`。

稀疏站点是声明的一部分：`write W[LMUL in [A,B]]` 与 `bind W[LMUL in [A,B]]` 合法；与 `bind W[LMUL]` 不合法（多出 C）。新增 `M16` 时，只有**全成员**站点会被要求补绑定。

### 3.6 投影（C6）

投影不是新关键字，也不写在 SSDL 里；它们属于目标 profile（与 `set` 的 `inst(attr)` 属性 schema 同一层）。语言只规定：

- 投影名在 profile 中唯一；
- 参数必须是已声明维度或实例参数；
- 结果类型是整数或整数列表；
- 求值在 norm 阶段完成，不进入记录。

### 3.7 名称格式（C7）

- `name_format` 只能包含一个字面量 `{value}`；
- 展开顺序按 `dim_index` 中轴的出现顺序；
- 若两个成员展开出同名标识符，报 `duplicate name`，不做自动去重；
- `worst(AXIS)` 固定用 `_WorstCase` 后缀，不受 `name_format` 影响。

## 4. norm 增量

```text
machine X : F(a, b) { body }
  → machine X { body ++ F.body[params := a, b] }

set A = [v1, v2] : kind = dimension, name_format = "_ {value}"
  → A 是目标级轴；不发射记录

write Base[A];
  → write Base_v1; write Base_v2;            [按 name_format]

bind Base[A] -> [...]
  → bind Base_v1 -> [...]; bind Base_v2 -> [...];

Base[A in [v1]]
  → Base_v1;                                  [只展开列出的成员]

Base[worst(A)]
  → Base_WorstCase;                           [单个伪成员]

latency = cycles(LMUL, 8, 1, 512)
  → 宿主 profile 求值后写入常量
```

展开后的文本就是 v1.0 SSDL，因此 `emit_td.py`、`-load-records`、`equiv.py` 全部复用。

实现：`parser.load_source` 以 `kind = dimension` 为标记自动调用 `family_expand.expand`，
所以 `validate.py` / `emit_td.py` / `diagnose.py` 可以直接吃族源；`validate.py` 还会对展开文本
跑 `check_coverage`，缺绑定按 error 报出。

## 5. 例子：SiFive7 的 VLDE 子族

```text
set LMUL = [MF8, MF4, MF2, M1, M2, M4, M8] :
    kind = dimension, name_format = "_{value}";

machine siFive7(vlen: INT) {
    resource VCQ : units = 1;
    resource VL  : units = 1;

    write  WriteVLDE[LMUL];
    write  WriteVLDE[worst(LMUL)];

    bind   WriteVLDE[LMUL in [MF8, MF4, MF2]] -> [VCQ, VL] {
        latency = 4;
        release = [1, 2];
        acquire = [0, 1];
    }
    bind   WriteVLDE[LMUL in [M1]] -> [VCQ, VL] {
        latency = 4; release = [1, 3]; acquire = [0, 1];
    }
    ...
    bind   WriteVLDE[worst(LMUL)] -> [VCQ, VL] {
        latency = 4; release = [1, 17]; acquire = [0, 1];
    }
}

machine sifive-7-series : siFive7(512) {
    ...
}
```

这个例子的 8 条记录已由 `tests/ssdl/sifive7-vlde.ssdl` 对上游逐字段验证（`check.py` 的 `sifive7_vlde_family_matches_upstream_values`）。

## 6. 非目标

- 通用元编程：递归、宏、自定义函数、条件代码生成。
- 任意字符串拼接：`name_format` 是唯一的受控替换。
- x86 folded pair（`X86Schedule.td:54`）与宽度族（`:78`）：记为 backlog。
- 让 `machine` 参数进入标识符：族参数只影响数值，不影响名字。
- `itineraries` 的任何改动。

---

## 7. 开放问题

1. **多维名字顺序**：`WriteVLSEG` 的 NF/EEW 在 base 内、LMUL 在后；当前规则能做到，但需要每个站点重复 `[NF, EEW, LMUL]`。是否允许在维度声明里给一个“默认拼接顺序”？暂不引入。
2. **成员级覆盖差异**：SCR345 的 SCR3（31 条）与 SCR4/5（67 条）共用源。v1.2 用稀疏成员表达；是否需要“成员组”抽象，待全模型实验。
3. **`fp_latencies` 这类枚举轴**：当前用 BOOL 选择器；若枚举值超过 2 个，需要新类型，但会破坏“只有 INT/BOOL”的简洁性。
4. ~~全模型压缩源~~ → 已完成：`docs/examples/sifive7-family.ssdl` 3746 行展开为 12375 行，write/read/variant/InstRW 齐全；四组 `equiv.py` 全部 `records match`（SiFive7 ×3 + Andes45）。
