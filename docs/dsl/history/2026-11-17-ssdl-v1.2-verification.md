## 0. 结论

| 断言 | 证据 |
|---|---|
| 14 个 RISC-V 调度模型全部可被 SSDL 1.2 表达并复现 | `equiv.py`：14/14 `records match` |
| 该结论不依赖 TableGen 的展开 | 直读 `--records-json` 的路径同样 14/14 |
| 真实模型上没有“不可能生效”的构造 | 诊断基线 0 个 error |
| 字段语义与源码直觉的偏差已被定位 | 1 个 warning（NanHu `loop_micro_op_buffer`）+ 两类 note |
| v1.2 的机器参数与数值投影在真实公式上可求值 | SiFive7 VCompress：3 个 VLEN × 4 个 SEW 全部命中上游值 |

## 1. 链路

```text
family.ssdl（作者手写，v1.2）
   │  parser.load_source：kind = dimension 触发 family_expand
   ▼
v1.0 SSDL 文本
   │  validate：sort / 覆盖性 / 效果诊断
   ▼
emit_td：records 表 + TD 文本（同一份数据的两个打印）
   │                                   │
   │ llvm-tblgen -print-records         │ expand_records（schema 展开）
   ▼                                   ▼
generated.rec                        records 展开视图
   └────────────── equiv.py ───────────┘
              与 $SSDL_CACHE/riscv.rec 比较
```

每一环证明什么：

- `family_expand`：压缩写法与展开写法是同一份语义（展开结果可重新解析，旧产物字节一致）。
- `validate`：覆盖性是错误的，就报错；`check_coverage` 挂在 `validate.py`。
- `emit_td`：records 表是 SSDL 的产物，TD 只是它的打印机。
- `equiv`（tblgen 路径）：SSDL 生成的 TD 能被 TableGen 接受，且展开后的调度语义与上游一致。
- `equiv`（直读路径）：上面的“一致”不是 tblgen 帮忙凑出来的。

## 3. 诊断基线

`data/riscv-sched-diagnostics.csv`：

- **error 0**：没有模型写出“看起来有效、实际不可能生效”的构造。
- **warning 1**：`XiangShanNanHuModel` 的 `LoopMicroOpBufferSize = 48`。上游注释是
  “Instruction queue size”，但唯一消费者是 TTI 的 unroll 阈值；MachineScheduler 与
  llvm-mca 都不读它。
- **note 主体**：`AcquireAtCycles`（跨模型约 2.6 万处）与 `Unsupported`（约 3.6 万处）。
  - `acquire` 只在 CodeGen 的 hazard/scheduler 生效，llvm-mca 直接建
    `CycleSegment(0, release)`。
  - `unsupported` 让 CodeGen 回退，但让 llvm-mca 对指令硬报错。
- 同一 `(level, message, effect)` 聚合成一行 `(xN)`；否则 `--verbose` 每个模型 4.2k 行。

## 4. v1.2 表达式验证

fixture：`tests/ssdl/sifive7-vcompress-family.ssdl`。公式取自上游
`RISCVSchedSiFive7.td`：

```text
SiFive7GetCyclesVCompress: cycles = ceil(VLEN / SEW) * LMUL
WriteVCompressV (LMUL=M1): latency = 7 + cycles, release = [1, 8 + cycles]
```

SSDL 写法（机器参数 + 轴单位投影，norm 阶段求值）：

```text
machine VCompress(vlen: INT) {
    write WriteVCompressV_M1[SEW];
    bind WriteVCompressV_M1[SEW] -> [], latency = 7 + vlen / SEW, acquire = [0, 1], release = [1, 8 + vlen / SEW];
}
```

结果（latency，release 恒为 `[1, latency+1]`）：

| VLEN \ SEW | 8 | 16 | 32 | 64 |
|---|---:|---:|---:|---:|
| 128 | 23 | 15 | 11 | 9 |
| 512 | 71 | 39 | 23 | 15 |
| 1024 | 135 | 71 | 39 | 23 |

12 个值全部与 `$SSDL_CACHE/riscv.rec` 中的上游记录一致。测试同时覆盖：

- `INT` 机器参数进入数值表达式；
- 维度成员的单位作为投影（`SEW` = 8/16/32/64）；
- `/` 必须整除，否则报错（不是静默 floor）；
- 实例 body 与族 body 共享同一参数环境。

## 5. 已知边界

1. **多实例族的资源命名**：resource 是全局 TableGen def。一个带资源的族如果有多个实例，
   要么每个实例声明不同名字的资源，要么只能一文件一实例。上游用
   `NAME # "SiFive7PipeA"` 拼名字，而 v1.2 明确禁止参数参与标识符拼接。
2. **没有条件表达式**：`BOOL` 参数不能选择数值分支；`latency = has_fast ? 4 : 7 + c`
   这类上游写法只能拆成不同族或由 host profile 投影。
3. **多行语句**：只有 `set` 声明会跨行合并；`bind`/`machine` 的字段必须写在一行
   （fixture 的 `release` 就因此与 `latency` 同行）。
4. **投影属于 host profile**：语言只规定调用契约，`worst`/`legal_sew`/`cycles` 的求值
   不在语言内。
5. **匿名记录编号**：直读路径会生成自己的 `anonymous_N`；比较不把编号当作契约。

## 6. 复现

```bash
# 14 模型：mine → validate → emit → tblgen → 两条 equiv
python3 tools/ssdl/family_sweep.py --records $SSDL_CACHE/riscv.rec --out $SSDL_CACHE/sweep-final

# 诊断基线
python3 tools/ssdl/family_sweep.py --records $SSDL_CACHE/riscv.rec \
    --out $SSDL_CACHE/sweep-final --diagnose-only \
    --diagnostics-table data/riscv-sched-diagnostics.csv

# 单条直读比较
python3 tools/ssdl/equiv.py $SSDL_CACHE/riscv.rec \
    $SSDL_CACHE/sweep-final/SiFiveP800Model/flat.json \
    --in-model SiFiveP800Model --gen-model sifive_p870_dModel \
    --in-processor SIFIVE_P870_D --gen-processor sifive_p870_d
```
